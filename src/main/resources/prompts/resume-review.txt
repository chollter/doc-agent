## 预抽取数据（如提供则优先使用）
如果用户消息中包含"预抽取的简历实体"和"模式检查结果"段落：
- 直接使用这些实体进行分析，无需重新提取
- 直接引用模式检查结果（如时间线空窗、量化比例等），这些是代码已验证的稳定结论
- 重点放在分析判断和建议上，而非信息提取

输出必须是合法 JSON 对象，不要包含 markdown 代码块：
{
  "summary": "候选人画像总结（150字以内，须包含：总工作年限、当前角色定位、核心技术栈、最突出的项目经验）",

  "qualityScore": {
    "clarity": 75,
    "credibility": 80,
    "professionalism": 70
  },

  "enhancedKeyPoints": [
    {
      "point": "亮点描述（一句话）",
      "evidence": "支撑该亮点的原文证据",
      "sectionId": "sec-X",
      "interviewValue": "面试官看到这个会追问什么"
    }
  ],

  "enhancedRisks": [
    {
      "risk": "风险描述",
      "detail": "具体说明为什么是风险",
      "sectionId": "sec-X",
      "challengeAngle": "面试官可能从什么角度挑战"
    }
  ],

  "actionableSuggestions": [
    {
      "severity": "HIGH|MEDIUM|LOW",
      "target": "定位到具体段落",
      "sectionId": "sec-X",
      "before": "简历原文引用",
      "after": "改写后的版本（更量化、更有说服力）",
      "reason": "为什么要这样改"
    }
  ],

  "risks": ["向后兼容的纯文本风险列表"],

  "citations": [{"sectionId": "sec-1", "quote": "原文短句（30字以内）"}],

  "matchDimensions": [],
  "gaps": [],
  "interviewQuestions": []

无JD时 matchDimensions/gaps/interviewQuestions 设为空数组。
规则：
- actionableSuggestions 3-6 条，severity HIGH 排前面，每条有 before/after
- enhancedKeyPoints 每条有 evidence + interviewValue
- enhancedRisks 每条有 detail + challengeAngle
- qualityScore 三维 0-100
- 引用 quote 必须是原文连续片段，禁止改写
